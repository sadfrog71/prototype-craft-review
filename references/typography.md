# 字体与排版：按角色建立层级

用于文字系统、字号深浅、字体选择和嵌入的定向审查。先复用项目已有样式；没有清晰系统时再归并角色，不因本参考重设已认可的品牌或布局。

## 层级与尺度

字号的选择标准是目标场景中的可读性、信息优先级、版面比例和同类一致性，不以是否落在某个数值区间验收。

- **先定阅读基准**：根据受众、目标设备、阅读距离、内容密度与实际字体的字面大小，确定正文或主要操作文字的舒适尺寸。沿用已验证的项目基准；没有基准时用代表区域实看后确定。
- **再定角色关系**：识别品牌、标题、操作、正文、数据、辅助说明各自的任务，用字号、字重、色深与留白共同表达主次，不强制套固定倍率。门户大标题与业务分析页标题分开选择，品牌字标连同全局页头判断。
- **按内容和容器调整**：长标题、多行正文、密集表格和图表分别判断；先考虑换行、布局及信息取舍，不为塞满容器统一缩字。不同视口可采用明确的响应规则，不简单等比例缩放整页。
- **把有效选择归入系统**：优先整理为少量角色变量，让相同场景、相同角色跨页一致；确有用途或密度差异时允许角色变体，不逐卡片凭感觉指定新数值。

下表仅为桌面 Web 的常见起步参考，单位为 CSS px，行高为倍数；区间不代表最小值或最大值，可以按上述标准选用范围之外的尺寸。不得仅因字号超出参考范围就判为问题，也不为符合表格而破坏已合适的设计。

| 文字角色 | 字号参考 | 字重参考 | 行高参考 |
| --- | --- | --- | --- |
| 门户首屏主标题 | 40–56 | 600–700 | 1.15–1.3 |
| 业务页面标题 | 24–28 | 500–700 | 1.25–1.4 |
| 区块/卡片标题 | 16–20 | 500–600 | 1.35–1.5 |
| 导航、按钮、表单标签 | 14–16 | 400–500 | 1.4–1.5 |
| 正文、表单内容、常规表格 | 14–16 | 400 | 1.5–1.7 |
| 时间、来源、页脚等辅助信息 | 12–14 | 400 | 1.4–1.6 |
| 图表轴、图例与数据标签 | 12–14 | 400–500 | 按图表布局 |
| 核心指标数字 | 28–40 | 500–700 | 1.1–1.25 |

- 标题、正文和辅助信息有可辨差异即可；不要同时把每级的字号、粗细、颜色和字距都拉到最大。密集分析页可用更紧凑的标题，长文阅读可放大正文。
- 小号文字仍需易读；重要限制、错误、价格单位及关键分析标签不能降格成极小注脚。图表空间不足时减少刻度、折行或调整绘图区，不默认把文字缩到 9–10px。
- 用实际可用的字重。正文通常 400、操作或小标题 500、重点标题再选更粗；不要全站加粗，也不要把只有单字重的字体误当作完整字重族。检查浏览器合成粗体及实际观感。
- 中文正文通常不加额外字距；品牌字标和短英文副标可局部调整，在整页验证。段落行距与行长共同判断，不靠大字距制造留白；断行按语义和宽度取舍，不给桌面所有标题硬插换行。
- 数字、货币、小数、百分号、单位和中文对齐。可用等宽数字时检查字体支持；表格数值按比较任务右对齐，核心数字与单位适当分层，单位保留可读尺寸。不要为数值单独换一个基线不协调的字体。

## 文字颜色与背景

浅色界面可从三档中性色建立主次：标题/核心值 `#0F172A`，正文/导航 `#334155`，辅助信息 `#64748B`。这是适合白色及接近白色背景的示例，不是跨主题通用色板；品牌、链接和状态另按其语义设置。

- “次要”靠角色、位置、字号和留白共同表达，不能只把颜色调淡。同一层级保持一致；同一行公司的名称若没有更高信息优先级，不单独换字体、加粗或变黑。
- 以实际前景与背景计算对比，包括透明度、渐变、图片、选中和悬浮状态；不要用给整个组件降透明度的方式弱化说明。`#94A3B8` 之类浅灰在白底上不宜承担正常说明或图表标签。
- 以 WCAG AA 为可读性底线：普通文字至少 4.5:1；符合大号定义的文字至少 3:1（约 24px 常规或 18.7px 粗体）。具体豁免按[官方说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)，不把禁用态当作正常内容使用；测量通过后仍看小字与细笔画的实际表现。
- 深色或图片背景重新选色并核查，不能简单沿用浅色界面的灰度或批量反色。链接、状态与选中项不能只靠难分辨的色差传达含义。

## 字体选择与许可

先沿用已有合适且授权明确的字体。缺少合适中文 UI 字体时，可从[思源黑体 Source Han Sans](https://github.com/adobe-fonts/source-han-sans/blob/master/LICENSE.txt)或 [Noto Sans SC](https://github.com/google/fonts/blob/main/ofl/notosanssc/OFL.txt)二选一；两者官方发行采用 SIL OFL 1.1，允许依条款商用与嵌入。按实际下载版本核对随附许可，不把“免费”“系统自带”或某下载站的描述当授权依据，也不承诺绝对零侵权风险。

- 主界面通常一个适合中文阅读的字体家族即可。拉丁数字可先用同家族；有明确需求再搭配另一家族，核对 x 高、笔画、基线与宽度。不要为质感默认堆叠多套字体；字标的独立设计也不应传播到所有正文。
- 区分系统调用、网页嵌入、字体文件分发和修改字体。分发 OFL 字体时随包保留版权与许可；子集化、转换或改名按该版本许可核对保留字体名等要求。原版不为统一项目名称而随意改名。
- 需要稳定跨设备或离线显示时，再考虑本地 WOFF2 及所需字重。子集不能只覆盖静态截图：用户姓名、动态业务文字、生僻字、符号和后续新增内容需有合理覆盖或回退。避免为一次字号微调加入整套字体资产。
- 核心文字保持可选择、可搜索、可缩放；不要用 ImageGen 把普通标题、按钮和数据标签画成位图来解决字体问题。

## 核查与收敛

- 用实际效果验收字号：目标尺寸下能舒适阅读，重点与阅读顺序清楚，内容密度适合任务，长文字及数字单位不冲突，同类页面有一致规律。不能只核对字号表或以“越大越清楚”判断质量。
- “字体看着不一样”先分辨家族、缺字回退、字重、字号、色深、行高与字距，避免只凭截图归因于字体。CSS 声明正确、请求成功或字体检查 API 返回可用，都不单独证明每个字实际用了目标字体；必要时查浏览器实际渲染字体与字形覆盖。
- 在目标视口的实际尺寸看整页，再看标题、正文、表格、图表和页脚的代表区域。检查加载前后跳动、长名称、多行、数字单位、中文标点和缩放后的裁切；只验证当前授权终端，不借字体审查新增设备范围。
- 修改公共文字样式时复看使用它的相关页面；局部修正保持局部。合并被替代的局部覆盖，沿用项目已有变量，不另建平行主题。交付说明角色变化、已核实的字体来源与仍未验证的平台，不以格式校验冒充审美认可。
