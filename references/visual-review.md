# 视觉审查：从整体到细部

根据页面性质、用户要求与参考取舍。每项都要能回答“此处为什么影响识别、理解或操作”，不靠固定审美打分。

## 如何识别页面的重点

1. **先定这一页要完成的判断或动作**：用一句话说明用户是谁、来解决什么问题。个人待办、项目推进、组织比较和品牌展示的重点不同；不要先选“大图＋大数字”再往里填内容。
2. **按业务价值排主次**：结合决策影响、紧迫性、异常程度、发生频率与当前角色责任，挑出本页主任务及必要的辅助信息；某个金额最大、数据最多或视觉最容易画，并不证明它最重要。不必机械评分或强制只留一个数字。
3. **画面权重跟随任务权重**：用首屏位置、面积、对比、字级和留白突出主任务；摘要、证据、操作形成阅读与行动顺序。页级标题、筛选和说明不能层层堆叠，把真正工作内容挤出首屏。
4. **回到实际画面检验**：先看第一眼被什么吸引，再检查阅读路径是否回答“在哪里、当前状态或问题是什么、下一步做什么”。若最抢眼的是次要差额、装饰横幅或布局设置，调整它的权重；不能只因每块都做得完整就判为整体成立。
5. **通过下钻与返回复核**：重点能否定位到具体对象、依据和动作；切换项目或角色后重点是否随之变化。删掉无增量的标签与说明，同时保留对象身份、状态、范围和操作反馈；用同视口、同数据比较调整前后。

## 品味与质感如何形成

- 先形成适合此页面的简短判断：保留什么、突出什么、收敛什么，以及依据来自任务、品牌、参考还是用户反馈。不必每轮输出固定格式，也不把个人偏好当作通用审美。
- 看第一眼的视觉重点和随后的阅读顺序。标题、图形、数据、操作各自有位置，主次由比例、对比和留白共同形成；避免所有模块都同样抢眼，或克制到没有重点。
- 看疏密和节奏：相关内容靠近，模块之间有边界，信息量与所占空间匹配。卡片、横幅和插画依用途取舍，既检查缺失，也检查重复。不要每页固定加 Banner、三张卡片或同一口号。
- 看材料与图形语言是否协调：照片、插画、矢量图标、图表和界面表面可以共存，但需有清楚角色和统一色调、光向、透视或线条秩序。阴影、纹理、玻璃和立体效果按场景选择，不是“高级感”的默认配方。
- 看近处细节：边缘清晰度、基线、裁切、圆角、边框、按钮反馈和留白是否准确；再缩回整页判断是否协调。精修局部不能破坏整体品牌、信息密度和使用方式。

## 整体与信息层级

- 用首屏回答：用户现在在哪里、最重要的状态是什么、下一步能做什么。业务工作台重视待办与任务，展示页可把品牌或作品作为主角；不要把同一个大图、卡片和口号套给所有场景。
- 比较页面的重心、留白、对齐、疏密、内容长度与滚动次序。留白不足会难以扫描，过多会把核心信息推离视口；按实际内容判断，不按卡片数量机械评价。
- 对全程、节点状态、并行关系和数量差异，优先安排环形、轴、矩阵、趋势或对比图等适合的视觉形式；检查方向、图例、当前节点与下钻关系，配图不能代替业务图形。
- 标题、正文、次要信息、数字、按钮要有可读的层级。日期、统计、待办等是否同组取决于信息关系；如果用户明确要求分开，遵照其组织方式。颜色可辅助区分，但重要状态应有文字或其他可辨标记。
- 检查整页及多页的布局节奏、组件边距、圆角、分割线和阴影是否属于同一个系统；避免一处精美、其余页面像未完成稿。
- 用户持续否定某个区域时，先看它是否提供新信息和有效入口。分析页的宣传图文可能需要改成有数据和依据的分析模块，门户的主视觉则可能值得强化，不能互相套模板。

## 项目标题与平台字标

- 先分清标题角色：平台名称承担稳定品牌识别；具体项目标题承担业务对象识别；卡片和区块标题说明内容。动态项目名保留可选择、可搜索的文字，不因字标美化把所有业务标题变成图片。
- 项目标题连同项目编号、状态、负责人、切换和主操作一起编排；名称优先、概要退后，长名称换行或合理截断并可查看完整值，避免标题与按钮争空间。
- 平台字标放回整个页头，与Logo、分隔、导航和账号区看比例、基线、字面大小、字距、笔画与视觉重心。检查每个字是否因字体回退、字重或色深不同而显得断裂，不连续孤立加粗或逐字换色。
- 先复用现有品牌和字体系统。用户明确要求用 ImageGen 设计字标时，按其文字、配色与统一笔画要求实际生成，核对字形正确、无多余文字、透明边缘和小尺寸清晰度，并保留可访问的名称；不把这一方式推广到普通标题与按钮。
- 在原尺寸的整页和窄屏中复看，而非只看放大的字标。标题美化应提高识别和协调性，不能挤压业务内容或改变已认可的品牌关系；字体排查细节按需读 [typography.md](typography.md)。

## 色彩、文字和材料

- 主辅色、状态色、背景、对比度和材质服务于品牌与场景。克制不是只允许一种颜色；明确的高饱和、深色或装饰风格也可以合适。
- 在实际背景上检查可读性，包括弱提示、占位文字、状态标签与图像叠字；不要只看设计稿色值。必要时测量对比度，同时观察真实尺寸。
- 汉字、数字、单位、长项目名和换行应清晰；避免缩小正文来塞满内容。文字系统或授权是本轮重点时，读 [typography.md](typography.md) 的角色尺度、色深、许可和实际渲染核查；小修沿用已有系统。
- 区分品牌色、操作色、分类色与状态色：图表多分类可以丰富，警告/完成等含义保持稳定；不把“统一风格”机械解释为只能一种颜色。
- 结合主题看材质、光照、比例、轮廓、反射与近处细节。生成的图像若与现有角色或品牌有差异，应指出，不冒称是原始素材的精确复刻。

## 图标：含义、家族和实际尺寸

1. 先确认每个入口的动作和业务含义。不同功能不能仅为凑齐一套而共用误导性图案；状态色不能制造未发生的成功或告警。
2. 同功能跨端优先复用已认可素材；缺少某功能时按已有家族补充，匹配轮廓、透视、线重、底色、填充、色彩、阴影、尺寸与留白。
3. 平面、线性、双色或立体都可适用，选择依据是现有风格、位置权重、业务性质和用户偏好。不要把“更精细”误解成一律加立体、高饱和和复杂细节；也不要把“扁平”退化成无法区分的通用细线。
4. 在真实显示尺寸及不同像素密度下复看。检查缩小后的清晰度、重心、基线、留白、点击面积，以及位图图集的裁切、串图、白边、锯齿、噪点和背景融合。大图好看不代表小图可用。
5. 审查素材实际来源和授权边界。用户指定的标识或角色以现有可用素材为准；新增绘图应保留参考特征，不虚构官方身份或实际项目现场。
6. 小尺寸导航与操作图标优先选含义准确的标准矢量家族；生成的立体或位图图标用于确有价值的识别层级。不要借用语义不符的图案凑齐一组；采用图集时实际检查映射、缩放与裁切，加载成功不证明图标正确。

## 配图与场景

- **先选位置和任务**：检查品牌区、项目头、摘要/重点提示、内容卡片与空态，明确哪里需要行业识别、场景解释或视觉锚点。重要区域并非都需要图片；主任务由业务记录或图表更好表达时，保留对应内容，不拿大图填空或重复标题。
- **先安排布局，再生成**：确定目标比例、显示尺寸、主体位置、文字安全区、裁切方式与背景关系，再形成提示词。例如左侧放重点和动作、右侧放工程场景时，画面应为文字留出干净区域；标题、状态、数字与按钮保持原生可交互，不能整块烘焙到背景图。
- **用全局风格约束素材**：提示词带上用途、行业对象、已认可的配色和材质、明暗与光向、画面密度、主体位置和留白。先看已有素材能否复用；有位图缺口时按主入口实际调用 ImageGen。用户否定深色或某种材质后替换该方向，不叠加旧效果；只读评审不生图。
- **接入页面后验收**：看实际尺寸的清晰度、主体完整性、透明边缘、图文对比和留白，检查桌面/目标窄屏裁切、文字按钮遮挡及离线加载；必要时换构图或裁切。图片生成成功不等于接入成功，资源请求成功也不单独证明图片已正确解码显示。
- 从全局安排哪些位置需要配图、承担什么任务、可共用哪些素材。通用项目封面或用户明确要求统一配图时可以复用；仅当图片需要区分真实对象或传达不同内容时再分别制作，不要求每个项目维护一张独有图片。也检查重复配图是否占空间却没有信息增量，不能只生成后放进一个角落就算完成。
- 已指定角色形象时使用可用的角色资产，不用同名字样或无关通用图标代替。有角色连续性时检查面部、衣着、颜色、道具和比例；场景则看光向、透视、尺度、空间关系与实用细节。真实项目信息不足时把概念图与现场证据区分。
- 对地图、流程图、工程图和数据图，重点检查事实、方向、标注、比例与图例，不因图像漂亮就当作准确技术图。

## 对比与反馈

- 改版前后尽量固定视口、数据、页面和滚动位置。指出改善了什么，同时检查是否牺牲了原有优势。
- 用户说“太空”“普通”“太突出”等，定位具体模块：内容密度、尺寸、信息权重、颜色还是材质；针对原因调整，而不是机械全局加内容或改色。
- 参考可以提供内容、语气、风格或布局中的任一部分；用户只授权其中一项时不要把其他部分视为必须复制。
- 修正后看实际尺寸、所在区域、整页与相关页面，检查重复标签、说明、装饰是否可删。删掉复述布局的说明，保留识别对象、范围、状态与行动所必需的信号；“让布局自己说话”不等于取消导航选中态、必要概要或业务分区。取舍需给具体理由，不靠“高级”“现代”或主观分数代替判断。
- 复用项目已有组件与样式来源；试验方案定稿后在改动范围内整理被替代的覆盖规则，避免字体、间距与颜色层层覆盖造成跨页冲突，不借此重构无关代码。
