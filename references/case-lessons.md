# 一次双端业务原型迭代的可迁移经验

这些是带条件的案例，不是对所有项目的固定风格或用户永久偏好的推断。

1. **新方案被认为不如原版**：先查看两版实际画面，分辨原版的信息密度、任务位置和用户认可的结构，再做针对性调整。调用设计技能、增加卡片或换配色本身不证明效果变好。
2. **移动端上方过空**：先判断空的是内容、层级还是位置。可把真实待办、常用入口或项目概况前移，但需按实际使用频率选择，不能只靠新增装饰填空。参考图可能仅供借鉴内容，不代表用户要求照搬布局。
3. **图标普通，复杂版又太突出**：先判断功能含义与尺寸，再统一轮廓、配色、线重和细节；此案例中用户选择较轻的扁平双色，其他项目可选择不同风格。跨端有现成同类图标时复用，缺失时补画同家族且含义清晰的图标。
4. **动作描述被更正**：用户把“闪光”改成“眨眼”后，移除被替代的光效，检查眼睑闭合再睁开，其他画面保持稳定；不同裁切尺寸要重新核对位置，并看实际播放与减少动态设置。
5. **外发需要本地打开**：整理入口和所有必要素材，写清先解压、分别打开哪一端，以及演示范围。验证时从最终压缩包重新解压，断网打开并走关键入口；浏览器模拟、手机真机和真实业务连接分别表述。
6. **字标美化后仍不协调**：某门户先给中间字上色、再换重字形，用户仍要求放回整个页头优化。应检查相邻Logo、字标、英文和导航的比例与重心，而非连续孤立换字体。页脚“像不同字体”也可能来自字重和颜色，先核对实际样式；不把某字体或统一深蓝当作跨项目标准。
7. **门户需要配图，分析页却要替换宣传卡**：在一个业务门户中，用户要求写实主视觉及各菜单横幅；在另一个分析型项目中，场景宣传卡改为上图下文后仍被否定，后续转为机会方向、客户、依据和明细入口。可迁移的是按页面任务判断素材与组件职责，不是“全站必须有 Banner”或“分析页不能有图片”；对话中的实现不自动代表用户已接受。
8. **换库和加色仍显普通**：分析图表已有悬浮、图例和下钻，用户仍要求更强表现力。需继续精修图形层级、绘图区比例、数值标注和交互细节，先用同数据的代表图复看；引擎接入、颜色增多和检查通过不等同于视觉完成。按需读 `chart-craft.md`，不因这个案例强制所有项目使用某图表库。

9. **业务平台越精简越像功能目录**：用户要求减少注释和标签，但进入业务后只有入口名称或字段定义，审批详情又混用了本笔申请与累计指标。应删解释性冗余，同时补足具体记录、对象关系、状态与办理依据；三类工作台按个人、项目、组织任务安排重点。不能把“让布局自己说话”解释为删掉识别业务的必要信息。
10. **生命周期从轴尝试改为环形**：用户希望全程节点、状态和重点更直观，环形用于概览，节点侧栏用于深入，原有甘特图继续解释工期。可迁移的是全程与局部衔接、实际位置与浏览选择分开；环形、七个阶段及示例节点均不是所有项目的固定规则，尚未获认可的方案不能记为用户定稿。

把用户对某次画面的反馈视为该任务的约束；跨项目保留“如何判断”和“如何验证”，不自动复制具体配色、角色、布局、字号或图标形式。
